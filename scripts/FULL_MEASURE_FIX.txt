FULL_MEASURE ROW CONSOLIDATION FIX
==================================

PROBLEM:
--------
The full_measure() command was writing TWO separate rows to the CSV file:
1. One row from measure_k2450() with Hall voltage/field data
2. One row from lockin_measure() with Lock-in X/Y/R/Theta data

This resulted in incomplete data representation - each measurement had only partial information.

SOLUTION:
---------
Modified the measurement workflow to consolidate all data into a SINGLE combined row:

1. Updated measure_k2450(skip_write=False) 
   - Added optional parameter skip_write
   - When True, suppresses automatic CSV row write
   - Used internally by full_measure() to prevent intermediate writes

2. Updated lockin_measure(skip_write=False)
   - Added optional parameter skip_write
   - When True, suppresses automatic CSV row write
   - Used internally by full_measure() to prevent intermediate writes

3. Refactored full_measure()
   - Calls measure_k2450(..., skip_write=True) to collect Hall data without writing
   - Calls lockin_measure(..., skip_write=True) to collect LockIn data without writing
   - Manually creates combined data_point with ALL fields:
     * Hall data: Hall_Voltage, Hall_Field, Meas_Current
     * LockIn data: LockIn_R, LockIn_Theta, LockIn_X, LockIn_Y
     * Settings: LockIn_Frequency, LockIn_Sensitivity, LockIn_R_lockin, etc.
     * Environment: Helmholtz_Current, Helmholtz_Field, Temp, In-plane_Field
   - Calls write_data_row() ONCE with measurement_type="Full"

BEHAVIOR:
---------
Before: full_measure() writes 2 rows (one with Hall only, one with LockIn only)
After:  full_measure() writes 1 row (with Hall + LockIn combined, NaN for missing values)

BACKWARD COMPATIBILITY:
-----------------------
standalone measure_k2450() still works as before (writes own row)
standalone lockin_measure() still works as before (writes own row)
Only full_measure() uses the new skip_write parameter internally
