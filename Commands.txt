================================================================================
                    MEASUREMENT SYSTEM COMMAND REFERENCE
                           v3 Script Commands
================================================================================

This document describes all available commands for the script editor.

================================================================================
SECTION 1: BASIC CONTROL COMMANDS
================================================================================

test
  Description: Test command to verify script parser is working
  Arguments: None
  Example: test

wait_for <event1> [event2] [event3] ... <additional_time_s>
  Description: Wait for one or more events before proceeding, then wait for additional time
  Syntax: wait_for <events...> <additional_time>  where last token is duration
  Arguments:
    event1, event2, ... - One or more events: "temp", "field", "helmholtz", "no_event", or "all"
    additional_time_s   - Extra wait time after events complete (float, in seconds)
  
  Event Details (executed sequentially in order specified):
    temp           - Wait for PPMS temperature to stabilize (PPMS only, no Helmholtz check)
    field          - Wait for PPMS field to hold (PPMS only, no Helmholtz check)
    helmholtz      - Wait for Helmholtz current to stabilize (no PPMS polling)
    no_event       - Skip checks and do a simple time delay (still abort-responsive)
    all            - Expands to: ['temp', 'field', 'helmholtz'] (all three sequentially)
  
  Sequential Execution:
    - Multiple events are processed in the order specified
    - Each event completes fully before the next event begins
    - Example: "wait_for temp field 5" waits for temp, then field, then additional 5s
    - Cannot mix 'no_event' with other events (it skips all checks)
  
  PPMS State Unknown Handling:
    - If PPMS reports field or temp value as 'nan' (indicating magnet problem or unknown state),
      the wait command treats it as STABLE and continues (rather than waiting indefinitely)
    - Example response from PPMS when field is unknown: ('0', ' nan', ' 1')
    - The timestamp when the field/temp became 'nan' is recorded in the data file Notes column
    - Example note: "PPMS field state unknown (field=nan) at 2026-02-18 14:23:45"
    - Scripts continue running with measurements recorded
  
  Helmholtz Stability Check:
    - temp: Only checks PPMS temperature, does NOT verify Helmholtz
    - field: Only checks PPMS field, does NOT verify Helmholtz
    - helmholtz: Checks that Helmholtz current matches target (within 1% tolerance)
    - Purpose: Verify the independent Helmholtz system is stable (PPMS cannot control this)
  
  Valid Examples:
    wait_for temp 5              # Wait for temp to stabilize, then 5 more seconds
    wait_for field 10            # Wait for field to hold, then 10 more seconds
    wait_for helmholtz 8         # Wait for Helmholtz current to stabilize, then 8s
    wait_for temp field 5        # Wait for temp, then field, then 5s (sequential)
    wait_for temp field helmholtz 2  # Wait for all three in sequence, then 2s
    wait_for all 5               # Wait for all three (temp, field, helmholtz) in sequence, then 5s
    wait_for no_event 10         # Simple 10-second delay without checks (abort still interrupts)
  
  Invalid Examples (will cause script validation error):
    wait_for temp                # ERROR: Missing duration (last token must be number)
    wait_for 5                   # ERROR: No events specified
    wait_for temp no_event 5     # ERROR: Cannot mix 'no_event' with other events
    wait_for invalid_event 5     # ERROR: Unknown event name
    wait_for temp field          # ERROR: No duration (last token must be number)

time_sweep <sweep_time_s> <time_gap_s>
  Description: Time-based loop that repeatedly runs the indented loop body for a fixed total duration
  Arguments:
    sweep_time_s    - Total loop runtime in seconds (float, >= 0)
    time_gap_s      - Delay between loop body executions in seconds (float, >= 0)

  Behavior:
    - Starts a timer when the command begins
    - Repeats all indented sub-commands until elapsed_time >= sweep_time_s
    - Sleeps time_gap_s between iterations (if time_gap_s > 0)
    - If sweep_time_s=0, the loop body is not executed
    - Fully stop/pause responsive like other loops

  Loop Body: Required (indented commands)

  Examples:
    # Run Hall measurement every 1 second for 2 minutes
    time_sweep 120 1
      measure_hall_field current=2 nplc=10 filter_count=15 tbm=0.2

    # Run as fast as possible for 30 seconds (no gap)
    time_sweep 30 0
      measure_lockin avg=5 sample_delay=0.02

for_loop <iterations>
  Description: General loop that runs the indented loop body a fixed number of times
  Arguments:
    iterations      - Number of loop iterations (integer, >= 0)

  Behavior:
    - Executes all indented sub-commands exactly 'iterations' times
    - If iterations=0, the loop body is skipped
    - Fully stop/pause responsive like other loops

  Loop Body: Required (indented commands)

  Examples:
    for_loop 10
      measure_lockin avg=10

    for_loop 3
      measure_hall_field
      wait_for no_event 1

SECTION 2: HELMHOLTZ FIELD CONTROL
================================================================================

set_helmholtz_field <field_Oe> <rate_Oe/s>
  Description: Set Helmholtz coil field to a specific value
  Arguments:
    field_Oe      - Helmholtz field in Oersteds (float)
    rate_Oe/s     - Ramp rate in Oe/s (float)
  Calibration: 2 × 341.71 G/A = 683.42 G per Ampere
  Example: set_helmholtz_field 100 5.0

scan_helmholtz_field <start_Oe> <end_Oe> <step_Oe> <rate_Oe/s>
  Description: Scan Helmholtz field with loop body
  Arguments:
    start_Oe      - Starting field (float)
    end_Oe        - Ending field (float)
    step_Oe       - Step size (float)
    rate_Oe/s     - Ramp rate (float)
  Loop Body: Indented commands that run at each step
  Example:
    scan_helmholtz_field 0 500 50 5
      measure_hall_field
      measure_lockin

sweep_helmholtz_field <start_Oe> <end_Oe> <rate_Oe/s> [gap_time=SECONDS]
  Description: Continuously sweep Helmholtz field with repeated measurements
  Arguments:
    start_Oe      - Starting field in Oersteds (float)
    end_Oe        - Ending field in Oersteds (float)
    rate_Oe/s     - Continuous ramp rate in Oe/s (float)
    gap_time      - Delay between loop executions in seconds (float, default: 0 = execute as fast as possible)
  
  Execution Pattern (3-stage):
    1. INITIAL STAGE: Set Helmholtz to start value, wait for stability (1% current tolerance)
       → Execute indented loop commands ONCE
    2. SWEEP STAGE: Begin continuous ramp from start to end
       → Repeatedly execute indented loop commands every gap_time seconds during the ramp
       → If gap_time=0, execute as fast as possible without delay
    3. FINAL STAGE: Reach stable endpoint
       → Execute indented loop commands ONCE more
  
  Loop Body: Indented commands that run at each stage
  Stability Check: Helmholtz current matches target within ±1%
  
  Features:
    - Continuous field ramp (not step-based like scan_helmholtz_field)
    - Repeated measurements at configurable intervals during ramp
    - Gap time controls measurement frequency (0 = fastest, >0 = fixed delay)
    - Measurements capture average Helmholtz field during each measurement function duration
  
  Example:
    # Sweep field continuously, measure every 2 seconds
    sweep_helmholtz_field 0 500 5 gap_time=2
      measure_lockin
    
    # Sweep field as fast as possible
    sweep_helmholtz_field -300 300 10 gap_time=0
      full_measure a

SECTION 3: DYNA (PPMS) TEMPERATURE CONTROL
================================================================================

set_dyna_temp <temp_K> <rate_K/min> <approach>
  Description: Set PPMS temperature to a specific value
  Arguments:
    temp_K        - Target temperature in Kelvin (float)
    rate_K/min    - Temperature ramp rate (float)
    approach      - One of: "fast_settle", "no_overshoot"
  Example: set_dyna_temp 300 5 no_overshoot

scan_dyna_temp <start_K> <end_K> <step_K> <rate_K/min> <approach>
  Description: Scan PPMS temperature with loop body
  Arguments:
    start_K       - Starting temperature (float)
    end_K         - Ending temperature (float)
    step_K        - Step size (float)
    rate_K/min    - Ramp rate (float)
    approach      - One of: "fast_settle", "no_overshoot"
  Loop Body: Indented commands that run at each temperature
  Example:
    scan_dyna_temp 300 400 20 5 no_overshoot
      full_measure a current=1e-6 resistance=10e3

sweep_dyna_temp <start_K> <end_K> <rate_K/min> [gap_time=SECONDS]
  Description: Continuously sweep PPMS temperature with repeated measurements
  Arguments:
    start_K       - Starting temperature in Kelvin (float)
    end_K         - Ending temperature in Kelvin (float)
    rate_K/min    - Continuous ramp rate in K/min (float)
    gap_time      - Delay between loop executions in seconds (float, default: 0 = execute as fast as possible)
  
  Execution Pattern (3-stage):
    1. INITIAL STAGE: Set temperature to start value, wait for stability (PPMS status=1)
       → Execute indented loop commands ONCE
    2. SWEEP STAGE: Begin continuous ramp from start to end
       → Repeatedly execute indented loop commands every gap_time seconds during the ramp
       → If gap_time=0, execute as fast as possible without delay
    3. FINAL STAGE: Reach stable endpoint
       → Execute indented loop commands ONCE more
  
  Loop Body: Indented commands that run at each stage
  Stability Check: PPMS temperature holding (status=1)
  
  Features:
    - Continuous temperature ramp (not step-based like scan_dyna_temp)
    - Repeated measurements at configurable intervals during ramp
    - Gap time controls measurement frequency (0 = fastest, >0 = fixed delay)
    - Measurements capture average temperature during each measurement function duration
  
  Example:
    # Sweep temperature continuously, measure every 3 seconds
    sweep_dyna_temp 300 350 5 gap_time=3
      full_measure a
    
    # Sweep temperature as fast as possible, measure lock-in signal
    sweep_dyna_temp 200 400 10 gap_time=0
      measure_lockin

SECTION 4: DYNA (PPMS) MAGNETIC FIELD CONTROL
================================================================================

set_dyna_field <field_Oe> <rate_Oe/s> <approach>
  Description: Set PPMS in-plane magnetic field to a specific value
  Arguments:
    field_Oe      - Target in-plane field in Oersteds (float)
    rate_Oe/s     - Field ramp rate (float, max 50 Oe/s)
    approach      - One of: "linear", "no_overshoot", "oscillate"
  Example: set_dyna_field 1000 10 no_overshoot

scan_dyna_field <start_Oe> <end_Oe> <step_Oe> <rate_Oe/s> <approach>
  Description: Scan PPMS in-plane field with loop body
  Arguments:
    start_Oe      - Starting field (float)
    end_Oe        - Ending field (float)
    step_Oe       - Step size (float)
    rate_Oe/s     - Ramp rate (float)
    approach      - One of: "linear", "no_overshoot", "oscillate"
  Loop Body: Indented commands that run at each field value
  Example:
    scan_dyna_field 0 2000 200 20 no_overshoot
      full_measure a

sweep_dyna_field <start_Oe> <end_Oe> <rate_Oe/s> [gap_time=SECONDS]
  Description: Continuously sweep PPMS in-plane field with repeated measurements
  Arguments:
    start_Oe      - Starting field in Oersteds (float)
    end_Oe        - Ending field in Oersteds (float)
    rate_Oe/s     - Continuous ramp rate in Oe/s (float, max 50 Oe/s)
    gap_time      - Delay between loop executions in seconds (float, default: 0 = execute as fast as possible)
  
  Execution Pattern (3-stage):
    1. INITIAL STAGE: Set field to start value, wait for stability (PPMS status=1 or 4)
       → Execute indented loop commands ONCE
    2. SWEEP STAGE: Begin continuous ramp from start to end
       → Repeatedly execute indented loop commands every gap_time seconds during the ramp
       → If gap_time=0, execute as fast as possible without delay
    3. FINAL STAGE: Reach stable endpoint
       → Execute indented loop commands ONCE more
  
  Loop Body: Indented commands that run at each stage
  Stability Check: PPMS field holding (status=1 or 4)
  
  Features:
    - Continuous field ramp (not step-based like scan_dyna_field)
    - Repeated measurements at configurable intervals during ramp
    - Gap time controls measurement frequency (0 = fastest, >0 = fixed delay)
    - Measurements capture average field during each measurement function duration
    - Respects maximum ramp rate of 50 Oe/s set by PPMS hardware
  
  Example:
    # Sweep field continuously, measure every 5 seconds
    sweep_dyna_field 0 2000 20 gap_time=5
      full_measure a
    
    # Sweep field as fast as possible, measure Hall effect
    sweep_dyna_field -1000 1000 50 gap_time=0
      measure_hall_field

SECTION 5: HALL BAR MEASUREMENTS
================================================================================

measure_hall_field [current=I] [nplc=N] [compliance_v=V] [voltage_range=RANGE] [filter_count=N] [tbm=S]
  Description: Measure Hall bar voltage and calculate magnetic field
  Arguments (optional):
    current=I        - Measurement current in mA (default: from GUI)
    nplc=N           - Number of power line cycles (default: from GUI)
    compliance_v=V   - Voltage compliance in volts (default: from GUI)
    voltage_range=RANGE - "1V", "10V", "10mV", "100mV", or "auto" (default: from GUI)
    filter_count=N   - 50/60 Hz noise filter count (default: from GUI)
    tbm=S            - Time before measurement: sleep after enabling current (s) (default: from GUI)
  Output File: Data_YYYYMMDD_XXX.csv as "Hall" measurement type
  Channels: Uses Keithley2450 with specified or GUI settings
  Calibration: Uses Hall_V2Gauss setting (default 10000/215 G/V)
  Notes:
    - Parameters with defaults use GUI values if not specified
    - All parameters optional; if omitted, uses corresponding GUI widget value
    - Specify only the parameters you want to override
    - TBM (time before measurement): Allows current to settle before voltage measurement
  Examples:
    measure_hall_field                                                    # Use all GUI defaults
    measure_hall_field current=1.5                                        # Override current only
    measure_hall_field current=1.5 nplc=10 voltage_range=10V            # Override multiple parameters
    measure_hall_field nplc=5 compliance_v=0.1 tbm=0.5                  # Different compliance and 0.5s settling time

continuous_measure_hall_field [current=I] [nplc=N] [compliance_v=V] [voltage_range=RANGE] [filter_count=N] [tbm=S]
  Description: Continuous-style Hall measurement without per-call source disable/enable
  Arguments (optional):
    current=I        - Measurement current in mA (default: from GUI)
    nplc=N           - Number of power line cycles (default: from GUI)
    compliance_v=V   - Voltage compliance in volts (default: from GUI)
    voltage_range=RANGE - Numeric value, optional V/mV suffix, or "auto" (default: from GUI)
    filter_count=N   - 50/60 Hz noise filter count (default: from GUI)
    tbm=S            - Time before measurement after enabling source (s, default: from GUI)
  Behavior:
    - If Hall output is OFF when command starts: enable output, wait tbm, then measure
    - If Hall output is already ON: measure immediately (no tbm wait)
    - Does not disable output at the end
  Output File: Data_YYYYMMDD_XXX.csv as "Hall" measurement type
  Examples:
    continuous_measure_hall_field
    continuous_measure_hall_field nplc=1 filter_count=5
    continuous_measure_hall_field current=1.0 compliance_v=2 tbm=0.2

measure_resistance [current=I | current_ma=I] [compliance=V] [nplc=N] [voltage_range=RANGE] [settle_time=S] [repetitions=N]
  Description: Measure sample resistance using K2450 current source + voltage sense
  Arguments (optional):
    current=I         - Source current in A
    current_ma=I      - Source current in mA (alias)
    compliance=V      - Voltage compliance in V (default: 10)
    nplc=N            - Integration time in power-line cycles (default: 1)
    voltage_range=RANGE - Voltage measure range in V/mV or "auto" (default: auto)
    settle_time=S     - Delay after sourcing current before read (seconds, default: 0)
    repetitions=N     - Number of reads to average (integer >= 1, default: 1)
  Notes:
    - Either current or current_ma is required
    - Uses fixed range when voltage_range is provided and auto when omitted/auto
  Examples:
    measure_resistance current=1e-3
    measure_resistance current_ma=0.5 voltage_range=20mV compliance=0.05
    measure_resistance current=5e-4 nplc=5 repetitions=3

measure_iv_curve mode=<current|voltage> shape=<shape> start=<val> [min=<val> max=<val> | stop=<val>] step=<val> [...optional args...]
  Description: Measure IV curve with K2450 using fast instrument-side sweep when available, with automatic fallback
  Required arguments:
    mode             - current or voltage
    shape            - Sweep shape (see list below)
    start            - Start setpoint (A for current mode, V for voltage mode)
    step             - Step size (same units as start, non-zero)
  Preferred sweep limits:
    min + max        - Preferred; explicit lower/upper sweep bounds
  Legacy sweep limits:
    stop             - Used when min/max are omitted
  Current-mode aliases:
    start_ma, min_ma, max_ma, stop_ma, step_ma
  Shape options:
    start_min_max_start
    start_max_min_start
    start_min_start
    start_max_start
    single
    return
    loop (alias of start_min_max_start)
    bidirectional (alias of start_min_max_start)
  Optional arguments:
    compliance       - V in current mode, A in voltage mode
    nplc             - Integration time in power-line cycles
    auto_range       - true/false for measurement autorange (default: true)
    settle_time      - Source delay per point (seconds)
    repetitions      - Per-point averaging count (integer >= 1)
    keep_output      - true/false (default: false)
    ramp_to_start    - true/false (default: true)
    reset_to_zero    - true/false (default: true when ramp_to_start=true)
  Mode-aware range options:
    source_range     - current mode: source current range (A; supports uA/mA/A suffix)
                      voltage mode: source voltage range (V; supports mV/V suffix)
    source_range_ma  - alias for source current range in current mode
    measure_range    - current mode: measured voltage range (V; supports mV/V suffix)
                      voltage mode: measured current range (A; supports uA/mA/A suffix)
    measure_range_ma - alias for measured current range in voltage mode
  Range auto behavior:
    - Omit source_range/measure_range to keep auto behavior
    - source_range=auto and measure_range=auto are accepted
  Validation rules:
    - min must be smaller than max
    - start must be larger than min and smaller than max
  Runtime notes:
    - Log reports point count, elapsed time, and engine mode (fast or point fallback)
    - Cleanup/ramp status message is intentionally not printed in status log
  Examples:
    measure_iv_curve mode=current shape=start_min_max_start start_ma=0 min_ma=-1 max_ma=1 step_ma=0.1 auto_range=true
    measure_iv_curve mode=current shape=start_max_start start=0 stop=1e-3 step=1e-4 source_range=1mA measure_range=0.2
    measure_iv_curve mode=voltage shape=start_max_start start=0 stop=0.5 step=0.05 source_range=2 measure_range_ma=10 auto_range=false

enable_hall_output [current=I] [compliance_v=V]
  Description: Enable Keithley2450 Hall source output
  Arguments (optional):
    current=I        - Source current in mA (default: from GUI)
    compliance_v=V   - Voltage compliance in volts (default: from GUI)
  Behavior:
    - Applies current/compliance settings then enables source
    - Keeps output enabled until disable_hall_output or other cleanup path
  Example:
    enable_hall_output current=1.0 compliance_v=2.0

disable_hall_output
  Description: Disable Keithley2450 Hall source output
  Example:
    disable_hall_output

correct_hall_field (internal, not directly called in scripts)
  Description: Iteratively correct Helmholtz current to achieve target Hall field
  Used by: set_ppms_field_and_fix_hall, scan_ppms_field_and_fix_hall
  Tolerance: ±1 G by default
  Max Iterations: 8
  Note: If tolerance is not reached within max iterations, execution continues

SECTION 6: LOCK-IN AMPLIFIER MEASUREMENTS

measure_lockin [what=PARAMS] [current=I] [series_resistance=R] [avg=N] [start_sens=IDX] [use_autorange=BOOL] [use_autophase=BOOL] [sample_delay=S]
  Description: Perform SR830 lock-in measurement with optional parameter control
  Arguments (optional):
    what=PARAMS      - Comma-separated parameters: "X", "Y", "R", "Theta" (default: from GUI)
    current=I        - Excitation current in Amps (default: from GUI)
    series_resistance=R - Series resistance in Ohms (default: from GUI)
    avg=N            - Number of samples to average (default: from GUI Averaging field)
    start_sens=IDX   - Starting sensitivity index 0-26 (default: 10)
    use_autorange=BOOL - "true" or "false" for autorange (default: true)
    use_autophase=BOOL - "true" or "false" for autophase (default: true)
    sample_delay=S   - Sample delay in seconds (default: 0.05)
  Output File: Data_YYYYMMDD_XXX.csv as "LockIn" measurement type
  Features:
    - Automatic time constant and filter setting from GUI dropdowns
    - Automatic phase alignment if use_autophase=true
    - Automatic gain (sensitivity) adjustment if use_autorange=true
    - Statistical averaging (configurable via GUI Averaging field or avg parameter)
    - Calculates sample resistance: R / I_excitation
  Output Parameters: X, Y, R, Theta (phase), plus all settings
  Notes:
    - Parameters with defaults use GUI values if not specified
    - Time Constant: GUI dropdown selects TAU_TABLE index (human-readable values shown)
    - Filter Slope: GUI dropdown selects 6/12/18/24 dB/oct
    - Sensitivity: GUI dropdown selects sensitivity index 0-26
    - Averaging: GUI Averaging field sets default number of samples (override with avg=N)
    - Specify only the parameters you want to override
  Examples:
    measure_lockin                                                    # Use all GUI defaults + auto tau/filter
    measure_lockin current=1e-6                                      # Override current only
    measure_lockin current=1e-6 avg=5 use_autorange=false            # Custom current and averaging, disable autorange
    measure_lockin what=X,Y,R avg=20 sample_delay=0.1               # Custom output parameters and averaging

continuous_measure_lockin [what=PARAMS] [avg=N] [sample_delay=S]
  Description: Continuous-style lock-in measurement without settling, autorange, or autophase. Excitation remains ON throughout.
  Arguments (optional):
    what=PARAMS      - Comma-separated parameters: "X", "Y", "R", "Theta" (default: from GUI)
    avg=N            - Number of samples to average (default: from GUI)
    sample_delay=S   - Sample delay in seconds (default: 0.05)
  Behavior:
    - Does not change sensitivity or excitation current
    - Does not wait for settling time
    - Keeps excitation ON throughout measurement and after (never turns off)
    - Writes a CSV row like measure_lockin
  Output File: Data_YYYYMMDD_XXX.csv as "LockIn" measurement type
  Examples:
    continuous_measure_lockin avg=10 sample_delay=0.02

SECTION 7: COMBINED MEASUREMENTS
================================================================================

full_measure [time_between=S] [hall_current=I] [hall_nplc=N] [hall_compliance=V] [hall_voltage_range=RANGE] [hall_filter=N] [hall_excitation=cycle|keep] [tbm=S] [lockin_what=PARAMS] [lockin_current=I] [lockin_series_resistance=R] [lockin_avg=N] [lockin_start_sens=IDX] [lockin_use_autorange=BOOL] [lockin_use_autophase=BOOL] [lockin_sample_delay=S]
  Description: Perform complete Hall + LockIn measurement in one operation
  Sequence:
    1. Measure Hall field (Keithley2450) with optional Hall parameters
    2. Close the active/default configured channel in switch
    3. Wait time_between seconds
    4. Run LockIn measurement (SR830) with optional LockIn parameters
    5. Open all channels
    6. Write single CSV row with all data
  
  Optional Arguments (Hall measurements):
    hall_current=I   - Measurement current in mA (default: from GUI)
    hall_nplc=N      - Number of power line cycles (default: from GUI)
    hall_compliance=V - Voltage compliance in volts (default: from GUI)
    hall_voltage_range=RANGE - Voltage range: "1V", "10V", "10mV", "100mV", or "auto" (default: from GUI)
    hall_filter=N    - 50/60 Hz noise filter count (default: from GUI)
    hall_excitation=cycle|keep - Hall source behavior (default: cycle)
      - cycle: Turn Hall source on, wait tbm, measure, then turn Hall source off
      - keep: Keep Hall source state/setting unchanged; if already ON, no tbm wait
    tbm=S            - Hall settle time before reading, seconds (default: from GUI)
  
  Optional Arguments (LockIn measurements):
    lockin_what=PARAMS - Comma-separated output: "X", "Y", "R", "Theta" (default: from GUI)
    lockin_current=I   - Excitation current in Amps (default: from GUI)
    lockin_series_resistance=R - Series resistance in Ohms (default: from GUI)
    lockin_avg=N     - Number of samples to average (default: 10)
    lockin_start_sens=IDX - Starting sensitivity index 0-26 (default: 10)
    lockin_use_autorange=BOOL - "true" or "false" (default: true)
    lockin_use_autophase=BOOL - "true" or "false" (default: true)
    lockin_sample_delay=S - Sample delay in seconds (default: 0.05)
  
  Optional Arguments (Timing):
    time_between=S   - Wait time in seconds between Hall and LockIn (default: 0.05)
  
  Output File: Data_YYYYMMDD_XXX.csv as "Full" measurement type
  Output: Single CSV row containing all Hall and LockIn parameters
  Notes:
    - Parameters with defaults use GUI values if not specified
    - Hall time constant and filter NOT overridable (fixed from GUI at measurement time)
    - LockIn time constant and filter automatically set from GUI values at measurement time
    - Specify only the parameters you want to override
  
  Examples:
    full_measure                                                                      # Use all GUI defaults
    full_measure time_between=0.1                                                    # Just change wait time
    full_measure hall_current=1.5 lockin_current=1e-6 lockin_avg=5                   # Override Hall and LockIn current
    full_measure hall_excitation=keep                                                 # Keep Hall source on between calls
    full_measure hall_voltage_range=10V lockin_use_autorange=false lockin_start_sens=15 # Custom ranges and sensitivity
    full_measure time_between=0.05 hall_nplc=10 lockin_avg=20 lockin_sample_delay=0.1   # Comprehensive parameter override

continuous_full_measure [time_between=S] [hall_nplc=N] [hall_compliance=V] [hall_voltage_range=RANGE] [hall_filter=N] [lockin_what=PARAMS] [lockin_avg=N] [lockin_use_autorange=BOOL] [lockin_use_autophase=BOOL] [lockin_sample_delay=S]
  Description: Continuous full Hall + LockIn measurement in one operation (single CSV row)
  Sequence:
    1. Measure Hall field (Keithley2450)
    2. Wait time_between seconds
    3. Measure LockIn (SR830)
    4. Write single CSV row with all data

  Continuous Behavior:
    - Does NOT close/open switch channels
    - Hall measurement always uses continuous mode (source remains ON between calls)
    - LockIn measurement keeps excitation unchanged and ON between calls
    - `lockin_use_autorange` default is false
    - `lockin_use_autophase` default is false
    - If either lockin auto flag is true, autorange/autophase run without changing excitation state

  Optional Arguments (Hall measurements):
    hall_nplc=N      - Number of power line cycles (default: from GUI)
    hall_compliance=V - Voltage compliance in volts (default: from GUI)
    hall_voltage_range=RANGE - Voltage range: "1V", "10V", "10mV", "100mV", or "auto" (default: from GUI)
    hall_filter=N    - 50/60 Hz noise filter count (default: from GUI)

  Optional Arguments (LockIn measurements):
    lockin_what=PARAMS - Comma-separated output: "X", "Y", "R", "Theta" (default: from GUI)
    lockin_avg=N     - Number of samples to average (default: from GUI)
    lockin_use_autorange=BOOL - "true" or "false" (default: false)
    lockin_use_autophase=BOOL - "true" or "false" (default: false)
    lockin_sample_delay=S - Sample delay in seconds (default: 0.05)

  Optional Arguments (Timing):
    time_between=S   - Wait time in seconds between Hall and LockIn (default: 0.05)

  Output File: Data_YYYYMMDD_XXX.csv as "Full" measurement type
  Output: Single CSV row containing all Hall and LockIn parameters

  Examples:
    continuous_full_measure
    continuous_full_measure lockin_use_autorange=true lockin_use_autophase=true
    continuous_full_measure time_between=0.1 hall_nplc=5 lockin_avg=20

set_ppms_field_and_fix_hall <field_Oe> <target_hall_G> [helmholtz_rate=0.1] [max_current_change=2.0]
  Description: Set PPMS field AND automatically correct Helmholtz for Hall stability
  Sequence:
    1. Set PPMS in-plane field using dyna.set_field()
    2. Wait for PPMS field to stabilize (status=0 "holding")
    3. Iteratively adjust Helmholtz current to fix Hall field to target
  Arguments:
    field_Oe       - Target in-plane field (Oe)
    target_hall_G  - Target Hall field (Gauss) to maintain via Helmholtz
    helmholtz_rate - Helmholtz ramp rate (G/s, default 0.1)
    max_current_change - Maximum allowed Helmholtz current correction per iteration (A total, default 2.0)
  Tolerance: ±1 G
  Max Iterations: 8 (for Hall field correction)
  Notes:
    - PPMS has ~1% perpendicular component that affects Hall reading
    - Helmholtz coil corrects for this perpendicular component
    - Hall probe reads used during correction are diagnostic only (logged, not written to data file)
    - If a single correction step requires current change > max_current_change: command aborts with error
    - If correction target exceeds Helmholtz hardware safety limits: command aborts with error
    - If correction fails to converge in max iterations: command continues to next command
  Example:
    set_ppms_field_and_fix_hall 1000 100.5
    set_ppms_field_and_fix_hall 1000 100.5 max_current_change=1.2

scan_ppms_field_and_fix_hall <start_Oe> <end_Oe> <step_Oe> <target_hall_G> [rate=10.0] [helmholtz_rate=0.1] [max_current_change=2.0]
  Description: Scan PPMS field, correcting Hall field at each point, optionally execute commands at each step
  Arguments:
    start_Oe       - Starting in-plane field (float)
    end_Oe         - Ending in-plane field (float)
    step_Oe        - Step size (float)
    target_hall_G  - Target Hall field at each step (float)
    rate           - PPMS field ramp rate (Oe/s, default 10.0)
    helmholtz_rate - Helmholtz ramp rate for correction (G/s, default 0.1)
    max_current_change - Maximum allowed Helmholtz current correction per iteration (A total, default 2.0)
  
  Loop Commands (optional):
    Indented commands execute at each field point
    Pattern: Same as scan_dyna_field (indented body syntax)
    Available commands: measure_hall_field, measure_lockin, full_measure, wait_for, etc.
  
  Workflow at Each Step:
    1. Set PPMS in-plane field to current setpoint
    2. Wait for PPMS field to stabilize
    3. Iteratively adjust Helmholtz current to maintain target Hall field (±1%)
    4. Execute all indented loop_commands at this field point
    5. Continue to next field point
  
  Tolerance: ±1 G Hall field correction
  Max Iterations: 8 (for Hall field correction at each step)
  
  Notes:
    - PPMS has ~1% perpendicular component that affects Hall reading
    - Helmholtz coil corrects for this perpendicular component independently
    - Hall probe reads used during correction are diagnostic only (logged, not written to data file)
    - If a correction step requires current change > max_current_change: script aborts with error
    - If correction target exceeds Helmholtz hardware safety limits: script aborts with error
    - Unlike early versions, this DOES perform measurements if loop_commands specified
  
  Examples:
    # Just field correction, no measurements
    scan_ppms_field_and_fix_hall 0 2000 200 100 rate=10.0
    
    # Field correction with measurements at each step
    scan_ppms_field_and_fix_hall 0 2000 200 100 rate=20
      measure_hall_field
      full_measure a
    
    # With explicit timing and parameter control
    scan_ppms_field_and_fix_hall -2000 2000 200 100 rate=10 max_current_change=1.5
      wait_for dyna_ready 2
      full_measure a lockin_current=1e-6 lockin_avg=10

set_lockin_time_constant <seconds>
  Description: Set SR830 time constant in seconds
  Argument:
    seconds        - Time constant in seconds (float)
  Conversion:
    - Converts from human-readable seconds to SR830 TAU_TABLE index
    - Warns if exact match not found (>10% difference)
    - Uses closest matching TAU_TABLE entry
  Valid seconds values (TAU_TABLE):
    10µs, 30µs, 100µs, 300µs, 1ms, 3ms, 10ms, 30ms, 100ms, 300ms,
    1s, 3s, 10s, 30s, 100s, 300s, 1ks, 3ks, 10ks, 30ks (indices 0-19)
  Notes:
    - Converts 1ks to 1000s, 3ks to 3000s internally
    - Used automatically in measure_lockin if GUI tau changed before measurement
    - Can be called before measure_lockin to set specific time constant
  Examples:
    set_lockin_time_constant 0.3      # Set to 300ms
    set_lockin_time_constant 1.0      # Set to 1 second
    set_lockin_time_constant 3.0      # Set to 3 seconds

set_lockin_sensitivity <index>
  Description: Set SR830 sensitivity index directly
  Argument:
    index          - Sensitivity index (integer 0..26)
  Valid index map:
    0=2 nV, 1=5 nV, 2=10 nV, 3=20 nV, 4=50 nV, 5=100 nV, 6=200 nV, 7=500 nV,
    8=1 uV, 9=2 uV, 10=5 uV, 11=10 uV, 12=20 uV, 13=50 uV, 14=100 uV, 15=200 uV,
    16=500 uV, 17=1 mV, 18=2 mV, 19=5 mV, 20=10 mV, 21=20 mV, 22=50 mV,
    23=100 mV, 24=200 mV, 25=500 mV, 26=1 V
  Behavior:
    - Applies SR830 sensitivity immediately
    - Updates GUI sensitivity selector to the chosen index
    - Affects subsequent lock-in measurements and auto-ranging start point choices
  Notes:
    - Use this command when you want fixed, deterministic sensitivity before a measurement
    - Out-of-range values (outside 0..26) are rejected by script validation
  Examples:
    set_lockin_sensitivity 10
    set_lockin_sensitivity 17
    set_lockin_sensitivity 26

set_lockin_filter <db_octave>
  Description: Set SR830 filter slope in dB/octave
  Argument:
    db_octave      - Filter slope: 6, 12, 18, or 24 dB/octave (int or float)
  Conversion:
    - 6 dB/oct → index 0
    - 12 dB/oct → index 1
    - 18 dB/oct → index 2
    - 24 dB/oct → index 3
  Notes:
    - Affects 99% settling time and measurement speed
    - Higher dB/oct = stronger filtering = slower response, lower noise
    - Used automatically in measure_lockin if GUI filter changed before measurement
    - Can be called before measure_lockin to set specific filter slope
  Examples:
    set_lockin_filter 6               # Light filtering, fast response
    set_lockin_filter 12              # Moderate filtering
    set_lockin_filter 24              # Strong filtering, best noise rejection

set_lockin_frequency <frequency_hz>
  Description: Set SR830 reference frequency in Hertz
  Argument:
    frequency_hz   - Reference frequency in Hz (float)
  Behavior:
    - Sets the SR830 reference frequency to the specified value
    - Updates the GUI frequency display to match the new value
    - Used to match lock-in measurement to excitation signal frequency
  Notes:
    - Default frequency: 173.0 Hz (configurable in GUI)
    - Frequency range depends on SR830 model (typically 0.1 Hz to 100 kHz)
    - Changes apply to subsequent measure_lockin commands
    - GUI frequency field automatically updated to show current value
  Examples:
    set_lockin_frequency 1234.5       # Set to 1234.5 Hz

set_lockin_current <current_A> [series_resistance=R]
  Description: Set SR830 excitation current using the external series resistor
  Arguments:

configure_channel <channel> <I+> <V+> <V-> <I->
  Description: Reconfigure a channel's switch routing numbers dynamically
  Arguments:
    channel        - Channel name: "a".."h"
    I+             - Routing number for I+ (1-8, must be unique within channel)
    V+             - Routing number for V+ (1-8, must be unique within channel)
    V-             - Routing number for V- (1-8, must be unique within channel)
    I-             - Routing number for I- (1-8, must be unique within channel)
  
  Behavior:
    1. Opens all switch channels first
    2. Updates channel configuration in GUI switch tab spinboxes
    3. Validates routing numbers are 1-8 and unique within channel
    4. Warns if routing numbers overlap with other channels (allows but logs warning)
    5. Writes configuration note to data file: "Reconfigured channel X: I+=N, V+=N, V-=N, I-=N"
  
  Validation:
    - All routing numbers must be integers between 1-8
    - No duplicate routing numbers within a single channel configuration
    - Cross-channel overlaps generate warning but are allowed (for sequential measurements)
  
  Use Cases:
    - Switch between different sample wirings without physically reconnecting
    - Swap routing across any configured channels (a..h) to measure different samples
    - Reconfigure mid-script to measure multiple samples with different physical connections
  
  Notes:
    - GUI spinboxes automatically update to reflect new configuration
    - Current switch state is closed (all channels open) before reconfiguration
    - Configuration note automatically appears in CSV Notes column for traceability
    - Runtime settings do not auto-persist on restart unless you save and reload configurations
      using Switch tab tools (Export Configurations / Load Configurations)
  
  Examples:

Automatic Data File Creation
  Location: Data_Route/ subdirectory or custom directory (from initialize_data_file)

  Headers: Automatically created with all column names and units

  LockIn_X_Error(V)      - Lock-in X standard deviation for the row's channel
  LockIn_Y(V)            - Lock-in Y value for the row's channel
  LockIn_Y_Error(V)      - Lock-in Y standard deviation for the row's channel
  LockIn_R(V)            - Lock-in magnitude for the row's channel
  LockIn_R_Error(V)      - Lock-in magnitude standard deviation for the row's channel
  LockIn_Theta(deg)      - Lock-in phase for the row's channel
  LockIn_Theta_Error(deg)- Lock-in phase standard deviation for the row's channel
  Frequency(Hz)          - Lock-in reference frequency
  Sensitivity(V)         - Lock-in full-scale sensitivity
  Resistor(Ohm)          - Lock-in series resistor value
  Output_Voltage(V)      - Lock-in excitation voltage
  Output_Current(A)      - Lock-in excitation current
  Time_Constant(s)       - Lock-in time constant in seconds
  Sample_Resistance(Ohm) - Sample resistance for the row's channel
  Sample_Resistance_Error(Ohm) - Resistance standard deviation for the row's channel
  Measurement_Type       - Row type (e.g., Hall, LockIn, Full, SessionInfo)
  Notes                  - User/script notes and automatic append/config markers

  Normalized Row Behavior:
    - Each measurement row carries a single channel label in Channel.
    - Lock-in/resistance values are stored once (no duplicated a/b-only columns).
    - In append mode, header must exactly match current schema; incompatible headers create numbered variant.
  Sample_Resistance(Ohm) - Calculated: R / I_excitation
  Measurement_Type       - "Hall", "LockIn", "Full", "SessionInfo", etc.
  Notes                  - Annotation text from add_note command (or empty)

NaN Handling
  - Missing values written as np.nan (blank in CSV)
  - Hall measurements: LockIn columns = NaN
  - LockIn measurements: Hall columns = NaN
  - Full measurements: All columns populated

TROUBLESHOOTING
================================================================================

Script Errors
  - Check script syntax in editor before running
  - Comments start with #
  - Indentation marks loop bodies (required for scan_* and scan_ppms_field_and_fix_hall)
  - Command parameters must match types (float for numbers, string for names)
  - Key=value parameters: no spaces around equals sign (e.g., current=1.5, not current = 1.5)

Measurement Errors
  - Hall measurement error: Check Keithley2450 connection
  - LockIn error: Check SR830 connection, autorange/autophase settings
  - PPMS error: Check DynaClass connection, field rate limits
  - Helmholtz stability warning: Output still ramping, may indicate coil heating or instability

Data File Issues
  - Automatic files in Data_Route/ with auto-increment naming (or custom via initialize_data_file)
  - CSV format can be opened in Excel/LibreOffice for analysis
  - NaN values appear as blank cells in spreadsheet applications
  - Notes column populated from add_note command; empty if no note specified

Time Constant Conversion Issues
  - set_lockin_time_constant accepts seconds (e.g., 0.3, 1.0, 3.0)
  - Internally converts to TAU_TABLE index 0-19
  - If exact match not found, uses closest value and warns in log
  - Common values: 0.3 (300ms), 1.0 (1s), 3.0 (3s), 10.0 (10s)

Sensitivity Selection Issues
  - set_lockin_sensitivity accepts integer indices 0..26 only
  - Index maps to SR830 full-scale sensitivity (2 nV .. 1 V)
  - Out-of-range index is a script validation error

Filter Slope Conversion Issues
  - set_lockin_filter accepts dB/octave: 6, 12, 18, or 24
